# Active and inactive editor measurements

`pnpm test:feature-budgets` reads the emitted public archive's own JavaScript static import closures. Optional entry closures subtract already loaded active modules. It records decoded, gzip level 9 and Node-default Brotli bytes plus content hashes, module counts and excluded bare imports. These are **own-module inventories**, not bundled sizes or browser transfer claims. The detector fails if optional catalogue/review/version/media/inline-rich-text UI enters the initial static closure. A deliberate oversized sample proves the ceiling is enforced. The baseline has 20% growth headroom plus a small fixed allowance; recalibration is an explicit `--record` action after review.

The production `performance.e2e.spec.ts` runs in a fresh cache-disabled Chromium context against the same synthetic storefront. It records actual JS/CSS ResourceTiming encoded/decoded/transfer bytes, request counts, action/readiness latency, CDP script execution time and long tasks for activation, first native panel, catalogue, review, versions, media, inline rich text, typing, save and panel reopen. A trace records JavaScript parse/compile events separately: their aggregate can include nested overlapping intervals and is not a wall-time metric. The report includes Node/Chromium versions, commit/dirty state and production build ID. `VE_RECORD_PERF=1` records the reviewed browser baseline; ordinary CI enforces it, including a deliberate oversized negative control.

The baseline includes Payload/React/Next/Lexical/Base UI peers in actual browser bytes. Native v3 field components are prepared during activation, so some Payload-owned rich-text dependencies may arrive then. Plugin-owned optional features retain genuine on-demand boundaries. This iteration preserves native preparation rather than introducing another field/schema rendering backend. No idle prefetch is enabled, so reduced-data/network users incur no speculative feature requests.

The first measured local baseline activated in about one second, transferred about 1.58 MB encoded / 5.35 MB decoded across 39 JS/CSS requests, and fetched no new chunks for the native panel or its reopen. Optional feature first use fetched separate chunks. These localhost/workstation numbers are diagnostic guardrails, not mobile-network or universal user latency promises. Browser byte/request ceilings allow 30% growth plus a small fixed allowance; action/execution ceilings account for CI variability. Existing 75-block input/frame and slow-save/caret/selection regressions remain separate behavioral gates.

Visitor isolation remains stricter: production resource observations, a delivered import graph, active positive controls and injected leaks prove authoring never enters anonymous/inactive resources. The independent packed consumer also compares enabled/disabled public resources byte for byte. Historical `baseline.json` and `installed.json` retain their original runtime/candidate identity and must not be mistaken for this branch's fresh acceptance.
